# 从笔记到书评

先明确哪本书、哪几条材料。用用户语言交付选题和文章，不向读者展示 JSON、散列或命令。整个过程可离线处理本机材料。保留原声，避免把读友或 AI 的判断写成读者感悟。

## 1. 圈定材料

已粘贴的材料由读者标明哪些是书中原文（quote），哪些是自己的想法（thought）；来源含混时先问一句，勿猜。微信读书用 books、notes --list 提供目录，只读用户选中的笔记。可选同书的共读书签，用 bookmark-resume 查到读者指定的版本。将输入写到本机私有临时文件，执行 `book-review --input <文件>`。任务结束后移除自己创建的临时文件。

任选一种 selection：

- 微信读书：`{"bookId":"书籍 ID","noteIds":["已选 ID"],"bookmarkIds":[]}`，可同时选该书的书签版本。
- 仅用共读书签：`{"bookmarkKey":"已选书签的 key","bookmarkIds":["版本 ID"]}`，支持手工书签。
- 手工笔记：`{"title":"山间来信","pasted":[{"chapter":"第一章","quote":"时间从不匆忙，匆忙的是我们。","thought":"我划下的是后半句。"}]}`。无需授权。

顶层先只传 selection。materials 返回 S1 等材料编号、来源类别、章节、可用摘录与截断标记。每批最多 100 条，进入写作的正文每字段最多 800 字符，合计 12,000 字符。材料较多时告诉用户覆盖了什么，允许缩小范围、粘贴更关键的段落重新选题。仅判断字段属于读者；划线不能直接当作读者赞同该命题的证据。

## 2. 让读者决定写什么

读这些材料，找两三个真正不同、能写成文章的主张。每个给一句论点、笔记依据、可能削弱它的材料，以及还需要什么才能写得扎实。优先找反例，找不到时标明“所选材料暂未提供反例”。纯假设的异议可作为待查问题。材料只够支持一个就给一个；连一个也站不住，传空 options，说明还缺哪类笔记并停在选题阶段。

沿用 selection，加入 options 后再次执行，检查确切出处。示例为字段格式：
```json
{"options":[{"claim":"让我停下来的是作者写人的那半句","support":[{"source":"S1","field":"thought","exact":"我划下的是后半句。"}],"counter":null,"gap":"还缺一条笔记，说明为什么是后半句打动你。"}]}
```

support 和 counter 的 exact 必须逐字出自指定字段。展示通过核对的选题后，问“你想写哪一个？”并等待实际选择。若用户之前已明确给出中心论点，可直接用相符的已核对选项。记录返回的 planId，后续请求沿用完整 selection 和 options。

## 3. 写正文，保留自己的声音

加入 planId 和从 1 起的 choice 可取回 chosen。围绕选定判断撰写连贯的开头、展开和收束；不同段落承担不同作用。文学作品尽量从具体措辞、人物动作或情节入手。按用户要求控制篇幅和语气。有意义的反例可以收窄主张；没有材料支撑的经历、作者意图、章节和页码不可补写。引用读者原话时用 thought，引用书中原文用 quote。没有个人想法时请读者补一句，或以文本评论口吻写作，不代写第一人称经历。

加入 draft 对象后预览。每段是有序的文本片段和引文片段；cite 从 1 起按 chosen.support 顺序编号，counter（如有）排最后。verbatim:true 由程序直接插入核对过的原话；false 仅插入脚注。书中引文和个人原话一律通过 cite 引用，不要在 text 中手打直接引语。脚注仅列正文实际用到的材料。

```json
{"draft":{"title":"让我停下来的半句话","paragraphs":[[{"text":"翻看笔记，我写下过这样一句话："},{"cite":1,"verbatim":true}],[{"text":"顺着这条笔记再读，问题落到了人怎样对待时间上。"}]]}}
```

把预览交给读者，可根据其意见修改。用户要求导出时，使用相同输入加 `--output <目标.md>`。若指定了 Obsidian Vault，就写到其指定位置；若没有指定 Vault，可交付本机 Markdown 的可点击路径。导出保留脚注、笔记编号、可用章节以及 AI 协助整理标识；遇到已有不同内容，选新文件名保留两个版本。
